# BACTrackManager Implementation Plan

Build a self-hosted BACtrack platform with a React Native capture app, a browser-based administration and map experience, and a NestJS backend. The first releasable slice supports authenticated users, teams, managed BACtrack devices, immutable test results, offline-safe synchronization, and LAN/home-lab deployment. BACtrack consumer-history import and Dawarich overlays follow only after the capture and tenancy contracts are stable.

Done means an operator can invite a teammate, select that teammate as the test subject, acquire an exclusive device lease, complete a physical BACtrack test on iOS or Android, recover from an interrupted upload without duplication, and see the result in the web dashboard. A user can choose disabled, upload-only, download-only, or bidirectional synchronization. A connected Dawarich instance adds movement points to the map without copying the full location history into BACTrackManager.

<Callout id="plan-status" tone="warning">

`docs/postgres-schema.sql` is a domain-model prototype, not an executable production migration. Implementation starts by replacing it with versioned Drizzle migrations, correcting tenant constraints, lease ownership, invitation null handling, authentication records, synchronization change feeds, and credential revocation.

</Callout>

## Product Workflow

1. A user registers, verifies email, and receives a private personal organization.
2. An owner creates a team, registers a BACtrack by serial number, and invites operators or viewers by email.
3. An operator chooses a team member as subject. The API validates both memberships and atomically creates the test session and exclusive device lease.
4. The mobile Turbo Native Module emits normalized connection and test events from the native BACtrack SDK. The app writes every event to encrypted local storage before rendering it.
5. Completion uploads one immutable result using a client-generated idempotency key. The API commits the result, releases the lease, appends audit/change-feed records, and publishes an SSE update in one logical operation.
6. The web dashboard displays personal/team history. The map always shows BAC markers and adds Dawarich location points when the user has a verified connection and download permission.

## Settled Technical Decisions

<Callout id="technical-decisions" tone="decision">

- Use a pnpm/Turborepo TypeScript monorepo.
- Use bare React Native with the New Architecture and a typed Turbo Native Module generated from a TypeScript specification. BACtrack remains behind a `BreathalyzerAdapter` interface so tests use a deterministic fake.
- Use Next.js App Router for web, NestJS for API and workers, Drizzle for typed PostgreSQL access plus explicit SQL migrations, BullMQ for jobs, SSE for server-to-client status, Redis for coordination, and MinIO/S3 for files.
- Target PostgreSQL 17 or newer. Use separate owner, migration, and runtime roles. Force RLS on tenant tables and keep composite organization foreign keys as a second boundary.
- Use short-lived JWT access tokens and rotating opaque refresh tokens stored hashed in PostgreSQL. Support password plus email magic-link login; defer passkeys and MFA.
- Use UUIDv7-compatible application-generated public IDs. Do not expose sequential database identifiers.
- Store BAC values exactly as reported in `%BAC` decimal form. Convert only for display; persist the source unit and payload.
- Treat captured readings and audit records as append-only. Corrections are new notes or flags, never edits to measured values.
- Use Bearer authentication for Dawarich when the installed instance supports it, because query-string keys can leak through logs. Pin the tested Dawarich OpenAPI contract by instance version.

</Callout>

## Scope and Non-goals

The first production slice includes iOS/Android capture, accounts, personal organizations, teams, email invitations, roles, device registration, exclusive leases, immutable readings, notes, four sync modes, web history, audit events, backups, and home-lab deployment behind HTTPS.

The first slice does not promise browser BLE, medical/legal evidentiary compliance, real-time location tracking by BACTrackManager, advanced analytics, public cloud multi-region operation, passkeys, or a desktop native BLE implementation. Browser BLE is a time-boxed feasibility experiment; Dawarich owns raw movement history.

The first migration set must enforce these invariants:

- Every tenant-owned row carries `organization_id`; composite foreign keys prevent cross-organization references.
- RLS is enabled and forced for runtime access. A transaction-local `app.user_id` and `app.organization_id` are set before any tenant query and reset by transaction completion. The runtime role does not own tables and has no `BYPASSRLS`.
- A personal organization is created with its owner in the registration transaction. The last owner cannot leave or be demoted.
- `device_leases` has one active row per device and one active row per session. Composite keys prove that device, session, mobile client, and holder belong to the same tenant. Acquisition locks the device row and retires an expired lease before insertion.
- Capture lifecycle and transport lifecycle use separate columns. A completed reading requires capture status `completed`; sync state never changes the measured state.
- `readings` and `audit_logs` reject runtime UPDATE/DELETE. Privacy deletion creates explicit redaction/tombstone records through a privileged maintenance procedure.
- Pending invitation uniqueness uses `NULLS NOT DISTINCT` or separate partial indexes for organization-only and team invitations. Removing a team revokes its pending invites instead of nulling only `team_id`.
- Sync changes use a monotonically ordered server sequence. Membership removal emits tombstones so cached team data is deleted from clients.
- Provider credentials are envelope-encrypted with key version metadata. Revocation clears ciphertext while preserving non-secret connection and audit history.

## Synchronization Protocol

Mobile stores sessions, events, readings, notes, local operations, remote entities, and cursor state in an encrypted SQLite database. A platform keystore/keychain-wrapped database key is mandatory. The queue never depends on React component lifetime.

Effective mode is the per-client override when present, otherwise the user default:

| Mode | Push local data | Pull cloud data | Managed team tests |
| --- | --- | --- | --- |
| `disabled` | no | no | no |
| `upload_only` | yes | no | yes |
| `download_only` | no | yes | no |
| `bidirectional` | yes | yes | yes |

Push rules: process operations in local sequence order, max 100 operations or 512 KiB per request, retry network/5xx failures with capped exponential backoff and jitter, persist per-item outcomes, and stop immediately when upload permission is removed. Idempotency is scoped to `(mobile_client_id, operation_id)` and request payload hash.

Pull rules: server order is a bigint sequence, pages contain at most 500 changes, cursor advancement and local page application share one SQLite transaction, tombstones remove inaccessible cached data, and an expired cursor triggers an authorized snapshot. Server timestamps decide ordering; device timestamps remain provenance only.

Changing from a non-upload mode never sends old readings automatically. The backlog screen shows item count, date range, and estimated size, then records explicit consent before enqueueing selected items.

## Implementation Phases

### Phase 0: Contract and hardware gates

Create ADRs for IDs, tenancy/RLS, auth tokens, immutability/deletion, sync protocol, native event vocabulary, and provider adapters. Obtain BACtrack developer approval/API key and physical devices. Pin minimum iOS/Android versions, React Native baseline, BACtrack SDK versions, PostgreSQL, Dawarich instance version, and SMTP behavior.

Exit gate: the native contract compiles through Codegen; OpenAPI contains stable errors and core DTOs; the permission/device matrix and unresolved provider fields are documented; no production schema is applied yet.

### Phase 1: Monorepo and infrastructure foundation

Create pnpm workspace, Turborepo tasks, strict TypeScript configs, lint/test/build CI, NestJS API and worker, Next.js shell, React Native shell, Docker Compose, PostgreSQL/Redis/MinIO health checks, structured logging, request IDs, and `.env.example` without secrets.

Exit gate: one command starts infrastructure and apps; CI runs lint, typecheck, unit tests, migration checks, API build, web build, and mobile native compile checks.

### Phase 2: Database, auth, tenancy, and invitations

Replace the prototype SQL with ordered Drizzle migrations. Add login identities, verified email, password hash, magic/reset tokens, hashed refresh sessions, registered clients, personal/shared organization kind, memberships, teams, invitation lifecycle fields, audit events, RLS policies, grants, and seed factories. Implement register, verify, login, refresh rotation, logout-all, client revoke, team CRUD, invite/resend/revoke/accept, and last-owner protection.

Exit gate: migrations apply to an empty database, rerun as no-op, and roll back on injected failure; cross-tenant and pooled-connection RLS tests fail closed; invitation races create one membership and one acceptance audit event.

### Phase 3: Physical BACtrack feasibility and native bridge

Implement the Codegen module on Android and iOS behind `BreathalyzerAdapter`. First use a fake adapter to complete UI/state tests, then connect one real supported unit on each platform. Normalize callback ordering and errors; persist events before UI transitions; handle permission, cancellation, backgrounding, and reconnects.

Exit gate: a real test reaches a measured result on Android and iOS; logs contain no API key or BAC value unless explicitly enabled in local development; all matrix cases have pass/fail evidence.

### Phase 4: Managed capture and immutable ingestion

Implement device registry, assignments, maintenance metadata, atomic session/lease acquisition, lease renewal/release/expiry recovery, event batch ingestion, idempotent completion, append-only readings, acknowledgement, notes, change-feed append, audit append, and SSE publication. Publish SSE only after commit.

Exit gate: two clients racing for one device yield one lease; crash recovery expires it; exact upload retries return the same reading; mismatched retry payloads return conflict; no cross-team subject can be selected.

### Phase 5: Offline database and directional sync

Implement encrypted local schema, operation journal, push batching, pull pages, atomic cursors, snapshot recovery, tombstones, four modes, immediate worker cancellation, network reachability handling, and explicit backlog consent. Add a debug screen that shows mode, queue size, last push/pull, cursor, and last error without exposing secrets.

Exit gate: capture offline, kill/restart the app, reconnect, and prove exactly one server reading; every sync mode produces zero prohibited-direction requests; membership revocation removes cached team data on next allowed pull.

### Phase 6: Web product and team workflow

Build dashboard, personal/team history, reading detail, team members, invitations, devices, maintenance, audit view, sync/client settings, notification preferences, and realtime session observer. Add accessible loading, empty, partial-failure, and permission-denied states. Support CSV export first; PDF/JSON follow after job infrastructure is stable.

Exit gate: an owner invites an operator, the operator tests another member, the subject acknowledges it, and authorized users see SSE/history updates while a viewer cannot mutate anything.

### Phase 7: BACtrack consumer import

Implement OAuth 1.0 only after authenticated provider docs and sanitized fixtures are available. Store request state and encrypted access credentials, run one import per connection, commit each page plus cursor atomically, deduplicate stable provider IDs, quarantine malformed records, show counts, and support disconnect/delete-imported-data behavior.

Exit gate: multipage import survives worker restart and duplicate pages without duplicate readings; token revocation removes ciphertext; raw payload retention/redaction tests pass.

### Phase 8: Dawarich map overlay

Add admin-approved server origin configuration, encrypted per-user Bearer credential, connection verification, strict no-redirect HTTP client, instance-version contract fixture, Redis response caching, date-window limits, BAC-only fallback, independently toggleable Dawarich points/tracks, nearest-point linking, and subject-consented single-point team sharing.

Exit gate: map works without Dawarich; connected users see points for a selected range; timeout returns BAC markers with a typed warning; SSRF/DNS-rebinding cases fail; disconnect clears credentials and linked-location deletion does not modify Dawarich.

### Phase 9: Operations and release hardening

Add notifications, maintenance reminders, export expiration, object cleanup, metrics, readiness/liveness, rate limits, backup/restore, key rotation, data export/deletion, dependency scanning, mobile release signing, upgrade/rollback runbooks, and a browser BLE feasibility report. Browser BLE ships only if real BACtrack GATT access succeeds without private undocumented protocol assumptions.

Exit gate: restore a fresh deployment from backup, rotate JWT/provider encryption keys, rehearse migration rollback, complete the physical-device matrix, and pass security/load/failure-injection suites.

## Deployment and Operations

The home-lab Compose deployment contains Caddy, web, API, worker, PostgreSQL, Redis, and MinIO on a private network. Only HTTPS web/API ports are published. PostgreSQL uses a persistent volume, daily encrypted logical backups, weekly restore verification, and explicit migration-before-rollout. Redis is disposable coordination state; PostgreSQL remains authoritative. MinIO lifecycle rules remove expired exports while retaining referenced attachments.

Readiness requires PostgreSQL, Redis, migration version, and object storage. External provider failures degrade their feature only. The API and worker use graceful shutdown, bounded retries, dead-letter visibility, structured JSON logs, metrics for queue depth/lease conflicts/sync lag/import failures, and alerts for backup failure or repeated provider authorization errors.

## Key Risks

- BACtrack provides native SDKs but no official maintained React Native library. The typed bridge and physical regression matrix are owned by this project.
- BACtrack consumer API details remain behind authenticated documentation. Phase 7 cannot start from public assumptions.
- Dawarich APIs can change between releases. Pin an instance version and contract-test its `/api-docs` output.
- Offline bidirectional sync and membership revocation are the highest-complexity application features. Do not begin them before the ordered change feed and tombstone contract exists.
- Location and BAC data are sensitive. Logs, exports, notifications, backups, and support diagnostics must default to redaction.
