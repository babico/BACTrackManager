# Native app

This React Native 0.87 app is local-first. On Android and iOS, BACtrack test results are stored in SQLite as AES-GCM encrypted payloads, with encryption keys held in Android Keystore or iOS Keychain. Manager connection and cloud sync are optional and configured in Settings. Users can inspect and explicitly clear the on-device history.

Run commands from the repository root:

- `pnpm --filter @bactrack/mobile-native start`
- `pnpm --filter @bactrack/mobile-native android`
- `pnpm --filter @bactrack/mobile-native ios` (macOS + Xcode only)
- `pnpm --filter @bactrack/mobile-native typecheck`
- `pnpm --filter @bactrack/mobile-native test`

Android builds require JDK 17, Android SDK Platform/Build Tools 37, Android NDK 27.1.12297006, and a connected physical Android device for BLE validation. Android emulators do not provide a reliable BACtrack BLE path. Local iOS builds require Xcode and CocoaPods; without a Mac, push the repository to GitHub and run the **iOS simulator build** workflow from Actions. It builds an unsigned simulator app for compile validation, not an installable iPhone IPA. Device/TestFlight distribution still needs Apple signing credentials and an Apple Developer account.

The Android and iOS apps use Bluetooth APIs directly and do not package or initialize the BACtrack vendor SDK. For the verified C6 profile they scan, connect, read available non-identifying model/firmware revisions, subscribe to device notifications, automatically request the device's coarse battery level, start a local breath test, and store the returned result in encrypted on-device history. iOS identifies remembered BLE peripherals using the OS-provided UUID (iOS does not expose BLE MAC addresses). Test readiness follows the native C6 GATT profile, rather than the BLE display name. The C6 battery level is a coarse 0–4 status, not a percentage; the interface shows only Low/Medium/High/Full. Protocol behavior was checked against the BACtrack Android SDK 2.1.3 artifact, but iOS hardware/firmware behavior still requires validation on a physical device and this app does not replace laboratory validation of sensor accuracy.

Analysis is the first app tab, history the second, and Manager/Bluetooth options are under **Settings**. Test location capture is independently toggleable and on by default; Android requests location permission only when starting a test. An available one-time location is encrypted with the local result and uploaded only through the selected Manager sync direction. When the account has a connected Dawarich instance, synced test coordinates are forwarded as OwnTracks points; without Manager sync, the result and location remain local. Sign in with the Manager email magic link (or paste the one-time link/token). Session tokens and Manager settings are AES-GCM encrypted with a key held by Android Keystore. Sync is off by default. After selecting an account/team, choose phone-to-Manager, Manager-to-phone, or both ways, then press **Sync now**. The connected BACtrack can also be registered to that account/team without uploading readings. Manager stores a random app-generated device identity, not the BLE address or a claimed manufacturer serial; firmware, hardware/software revisions, coarse battery level, and last-connected time are attached when available. Previously connected BLE devices are remembered encrypted on-device and can auto-connect when discovered; unknown nearby devices are never auto-connected. Team uploads require an owner/admin/operator role; choosing a team organization shares those readings with its members. The Manager API defaults to `http://192.168.21.2:3001` for this home-lab setup; change it in Settings when the API is hosted elsewhere. Use HTTPS outside a trusted private LAN. Breath analysis and encrypted local history continue to work when the Manager server is unavailable or disconnected.

Android app data is excluded from Android backup. iOS database files are excluded from iCloud backup and the encryption key is device-only in Keychain. Clearing app data or uninstalling the app removes the local database; Keychain item lifecycle follows iOS uninstall behavior and should be validated before relying on uninstall as secure erasure.
